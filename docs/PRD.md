## 2. 产品定义

### 2.1 产品目标（正交三目标）
1. **一套内核、多端复用**：以现有 Web 应用为唯一功能内核，通过构建层与平台适配层输出到 Web / Android / Windows 三端，避免三套代码库功能漂移。
2. **原生体验落地**：Android 与 Windows 端具备真实本地文件系统能力（选择保存位置、流式写盘、大文件不占 JS 内存），达到「生产可用」而非「网页套壳」。
3. **配置与分发生产化**：消除所有硬编码密钥/域名/站点码，配置由环境注入；产出可签名、可升级、可分发的多端安装包与公开 Web 站点。

### 2.2 用户故事
1. 作为**个人用户**，我希望在手机上安装云盘 App 并把云端文件直接保存到手机存储/SD 卡，以便离线查看和不依赖浏览器下载管理器。
2. 作为**桌面用户**，我希望在 Windows 上用原生窗口管理云端文件并自选磁盘目录落盘，以便大文件下载稳定、可断点续传、可长期保存。
3. 作为**分享接收方**，我希望在任意端打开分享链接即可查看和下载文件、无需登录，以便快速拿到对方发来的资料。
4. 作为**部署/运维者**，我希望通过环境变量注入后端地址、密钥和站点码，以便同一份代码可用于开发、测试、生产多套环境而不改源码。
5. 作为**发布者**，我希望各端有明确的版本号、签名与安装包（Windows x64 NSIS + portable），以便分发、升级与溯源。

## 3. 需求池（P0 / P1 / P2）

> P0 = 必须（生产发布阻塞项） ｜ P1 = 应该（体验与稳定性） ｜ P2 = 可以（锦上添花）

### P0 · 必须
- **R-01 构建工程**：引入 `package.json` + Vite/esbuild，产出 Web 静态包；README 与构建脚本同步更新（去掉「无构建步骤」表述）。
- **R-02 配置注入**：`endpoint` / `publishableKey` / `oauthRelayBaseUrl` / 站点码 / 分享域名改为构建期环境变量注入（如 `import.meta.env`），源码零硬编码；提供 `.env.example`。
- **R-03 平台适配层**：抽象统一能力接口（选择保存位置、流式写盘、打开外链、获取分享基址），Web/Android/Windows 各自实现，业务层只调接口。
- **R-04 Android 工程**：Capacitor 初始化，集成 NativeFs / SAF / MediaStore 插件，实现"选择保存目录 + 流式写盘"，`minSdk 26 / targetSdk 36`。
- **R-05 Windows 工程**：Electron 初始化 + preload IPC 流式写盘（主进程落盘，渲染进程不缓存整文件），禁用不必要 Node 集成。
- **R-06 分享基址解耦**：把 `location.origin` 与绝对 `/sw.js` 改为可配置基址 + 相对路径，使 Web 落地页域名与原生端内部页面解耦。
- **R-07 SDK 与依赖本地化**：移除运行时 CDN 强依赖（SDK、`client-zip`），改为构建期打包/本地 vendor，保留多源回退作为容错。
- **R-08 产物与签名**：Windows 产出 x64 NSIS 安装包 + portable 版；Android 产出可签名 APK/AAB；版本号统一 `1.0.0`。

### P1 · 应该

- **R-12 安全加固**：密钥不入库、分享链接签名 URL 过期提示、站点码透传兼容微信内置浏览器。
- **R-13 更新与兼容**：Electron 版本升级策略、Android targetSdk 36 权限与存储分区适配说明。

## 4. 端功能边界与验收标准

### 4.1 Web（公开分享落地页 + 完整网页版）
- **范围**：账号登录、文件管理、上传/下载、公开分享接收页、诊断工具全量保留；作为分享链接的公开落地入口。
- **必须**：无需安装、浏览器直接打开；公开接收页无需登录即可查看/下载；大文件流式下载（SW）不 OOM；CDN 依赖本地化后仍能在无外网 CDN 时加载 SDK。
- **验收**：
  1. `npm run build` 产出静态包，部署后核心流程（登录→上传→分享→接收下载）全通。
  2. 分享链接在 Web 端可打开，接收方免登录下载成功。
  3. 源码 `grep` 无硬编码 endpoint/publishableKey/站点码。
  4. 断开 CDN 域名后页面仍可加载并使用（走本地 vendor/打包依赖）。

### 4.2 Android（Capacitor）
- **范围**：复用 Web 内核全部功能；新增原生本地落盘能力；保留公开分享链接在浏览器/内置接收的能力。
- **必须**：文件可选择保存到手机存储/SD 卡（SAF/MediaStore）；大文件流式写盘；`minSdk 26 / targetSdk 36`；适配触控与移动端布局。
- **不做**：不重复实现业务逻辑；不内置固定后端域名（环境注入）。
- **验收**：
  1. 真机安装 APK，登录后可将云端文件保存到自选目录，文件管理器可见且内容完整（校验大小/哈希）。
  2. 500MB 级文件下载过程内存平稳，无 OOM。
  3. `targetSdk 36` 下分区存储权限流程正确，无权限崩溃。
  4. 生成可签名 release 包（签名配置待确认，见 §6）。

### 4.3 Windows（Electron）
- **范围**：复用 Web 内核全部功能；原生窗口 + 主进程流式写盘；保留公开分享链接接收。
- **必须**：Electron 主进程负责文件落盘，preload 暴露最小 IPC；自选磁盘保存目录；大文件流式写盘；禁用渲染进程 Node 集成。
- **不做**：不做独立后端；不改业务逻辑。
- **验收**：
  1. Windows x64 产出 NSIS 安装包 + portable 版，均可安装/启动。
  2. 通过原生对话框选择保存位置并下载，文件完整落盘（校验大小/哈希）。
  3. 1GB 级文件下载渲染进程内存平稳，不整文件缓存。
  4. 安装包带正确版本号 `1.0.0` 与应用名「个人云盘」。

### 4.4 跨端一致性
- 三端共用同一业务内核，登录/文件管理/上传/分享逻辑一致；仅平台能力接口实现不同。
- 配置全部来自环境，任何一端源码不含生产密钥或固定域名。
